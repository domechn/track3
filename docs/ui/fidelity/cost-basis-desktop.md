## Data gaps to review

The product's existing warning detection is the sole source. Present it as a table with Date, Coin, Amount and Reason, group headers sorted by reason, newest rows first within each reason, a reason filter, and pages of 50 data rows. The Amount header and cells align right. A group header repeats when its group crosses a page boundary. Ignore floating residue and fold entries whose absolute coin quantity is below `1e-8` **or** whose estimated absolute USD value is below `$0.01` into a single `Dust` summary line. Unknown or zero placeholder prices cannot satisfy the USD test; apply only the coin threshold. Format remaining amounts with thousands separators and at most eight decimals. Do not add persisted fields.

## Product behaviour

Records pages use the design rail, header and card positions. The bottom rail control opens Refresh, the Pro live total, Settings and the original Cost basis AI setup card. The ordinary capture keeps the source's 20 px header position. A real completed sync shows one timestamped status control and popover in the page header. Captures seed completed runtime status at 09:41.

Selecting a tax year persists and queries `1 Jan` through `31 Dec` of that year. For the current year, the subtitle and export note show the effective end date, `min(31 Dec, today)`. The input still displays the selected full year on reopening. Editing a date preserves the current table tab and page until the new report arrives. A new report resets the table page, data-gap page, and reason filter while retaining the selected tab. Method and range changes run the existing report query; the added chart context fetch runs only on first load and a data change.

The selected range uses the report's calculator values. The desktop page reads transactions and latest assets once per data change and reuses those rows when method or range changes. For an unmatched withdrawal, the view derives acquired date and cost from the same lot matching method used by the calculator, while proceeds and gain remain unknown. This attribution still needs a second calculator pass for a visible unknown withdrawal: the shared report does not expose consumed-lot details, and this UI-only task forbids changes to `src/middlelayers`. The page and its exports remain in USD, as before the fidelity pass. Dates and grouping follow the UI locale. A non-365 holding rule updates the rule text, holding notes, open-lot terms and subtotals. The days field is visible and editable for FIFO, LIFO and HIFO; average cost has no term rule.
