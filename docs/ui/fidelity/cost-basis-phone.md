## Data gaps requirement

Below the report, Data gaps to review uses the existing warning records only. A table presents **date, coin, amount, reason** in that order, with a reason selector and Previous/Next pagination of 50 rows. Amount cells stay on one line at 390 px; the columns use 24/15/25/36 percent widths, leaving at least 8 px around the NOVA amount. Dates wrap within their column when needed so English and Chinese leave at least 8 px before the coin; at narrower widths the table scrolls within its card. An amount whose absolute coin quantity is below `1e-8`, or whose estimated fiat value from an available report price is below `$0.01`, is folded into one “Dust” line for the selected range; that line can be selected as a reason. The UI uses at most eight fractional decimals and thousands separators for displayed coin quantities; a real amount never displays as zero. If no price exists, the fiat test cannot run. This is a display threshold only; report/export and stored data are unchanged. The second-page pager capture is `/tmp/fidelity/cost-basis/cost-basis-gaps-page2-phone.png`, populated through stored transaction shapes.

## Product data constraints

The selected-range average buy and sell prices and quantities use the existing transaction query for the active dates and asset type. Lots, chart gaps, and average rows also keep stock and crypto with the same symbol separate; duplicate lot headings show their type. Rows follow current stored portfolio value, which places SOL third even in the 2025 view. A missing side displays “–”; symbols with an unknown basis are omitted from the table. An unmatched transfer warning does not prove sale proceeds are unknown, and report totals continue to follow the existing engine. The sample SOL withdrawal is displayed from the existing gap detector, and its amount uses four decimal places in the banner, disposition, and Data gaps table. The default “365 days” holding copy follows the source; the engine tests an annual calendar anniversary at that setting, which can differ around leap years. Other selected thresholds are shown as days and passed to the report. The source rounds each lot's cost and market value to cents before summing; Track3's report retains full precision until display. Its totals and export use the same report values, causing the sample's one or two cent differences.

## Coarse-pointer accessibility outside the phone route

`src/style.css` keeps 44 px coarse-pointer targets for the shared source picker, chart mode buttons, and Settings export label. The desktop Playwright project renders desktop routes with a touch pointer; removing the source-picker rule made its “All sources” button 98 × 36 px and failed the touch-target check. These rules preserve the existing accessibility requirement on those shared controls and do not change mouse layouts or this screen's source comparison.
