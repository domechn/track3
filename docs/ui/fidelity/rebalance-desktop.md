## Behaviour and other variants

At 1600 px in dark mode, target inputs update the actual validated profile; `+ Set` starts a target for that asset. Target and minimum-trade inputs retain typed decimals while focused and format on blur. Buttons and inputs use tabular digits; KPI and Result values use normal numeric spacing because the source's `font:` shorthand resets their variant. Unavailable KPI values use the muted zero tone in the empty and invalid states. The trade share arrow is a separate muted 13 px span, 10.90625 px wide, matching the rendered source. The Export CSV button uses weight 500 and its helper is 13 px. Switch rows are 36 px high and trade table headers use a 16 px line height. Presets, normalization, tolerance, minimum trade, small-holding filter, stablecoin treatment, CSV export, and the saved-profile controls remain live. The stored trade mode, injected cash, small-holding threshold, and custom tolerance are editable in the advanced dialog. Turning the small-holding filter back on restores its prior threshold in this session; its first default is the base-currency value of USD 5,000, including the helper text when the switch is off. Target and tolerance changes show “Unsaved changes” with a visible Save action in the Rules header; failed or invalid saves retain that state. Clicking the Rules heading opens the advanced dialog for target types, additions, save, and reset; reset opens a confirmation with distinct explanatory copy. Loading uses the wide shell immediately; failed holdings/profile loads and partial snapshots show inline alerts, and partial snapshots pause trades and export. Profile, normalization, and option errors are visible even when the target total is 100%; invalid inputs block saving and trades. The Rules heading announces its visible label. Refresh, sync status, and the Pro live-value control sit in the rail while this wide layout is active; Assistant appears there only for Pro users, and the Goals badge announces unread alerts, including in the empty target state. Refresh progress spans the top of the main area. A price refresh from a previous day shows its date and a neutral dot. Date range is omitted here because the calculation uses the latest snapshot. The established Rebalance layout, assistant setup card, and quote-colour chart remain active below 1500 px, in the light theme at wide widths, and for saved profiles with asset-type or cash targets. Those profiles use the established calculator rows for drift and trade information because the design's per-asset input rows cannot represent their target kinds. The wide design omits `AISetupCard`, since its setup actions are available through the Rules controls and the legacy page remains available for type or cash targets. The existing hide-values control on Comparison is unchanged; Rebalance itself has no hide-values control. With System selected, OS appearance changes update the page layout immediately. No storage fields change.

## Remaining differences

**9 Nov 2026 layout audit:** rebalance 10.430% at 1280 × 800, dark, against the rendered source HTML (RGB channel difference sum > 60). The dense CNY fixture and working product state differ from the static reference; the page-specific visible differences are listed below.

UI42 uses the approved website-style neutral tile for asset marks. The older Rebalance page design renders those marks differently.

The zero-target trade area uses the shared centred icon and explanation; the source's empty panel predates this UI18 requirement. Target inputs, reserve calculation, and CSV content are unchanged.

The wide dark page places Refresh, sync and the Pro live-value control in the unified rail without taking a 50 px strip above the content. Its regular TopBar remains visible in light mode and below 1500 px; those layouts have no matching 1600 px dark source capture. The 10/30/50/100/All presets and date picker are hidden only in the wide dark plan because its calculation always uses the latest snapshot. The shared rail's tile, logo and control differences from the illustrative source are detailed in [navigation.md](../navigation.md).

The 8 Nov 1600 × 1000 captures in `/tmp/fidelity-desktop/rebalance/` differ from the design HTML captures in `/tmp/fidelity-source/` by **1.049%** for the plan, **0.504%** for empty, and **1.744%** for invalid within the shared viewport. A pixel counts when any RGB channel differs by more than 40. The design pages extend to 1405, 1215 and 1289 px while Track3 scrolls inside its 1000 px desktop shell. Padding the lower design area with the shell ground yields **2.392%**, **0.937%**, and **1.851%** respectively. The source `getBoundingClientRect()` and `getComputedStyle()` check places the KPI card at `(84, 88, 1488, 108)` with `rgb(19, 18, 23)` fill; the app card begins at the same coordinates.
