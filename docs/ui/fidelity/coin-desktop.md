## Interactions, unavailable variants and data rules

Breadcrumb and `Open cost basis` navigate; chart and transaction filters change visible data, source rows are real holdings, each pencil opens one edit flow, sheet Close and dialog Cancel restore focus. Maintain hide-values masking, quote-colour reversal, accessible names/focus, sync status popover, and product's existing date range and query behaviour. Real price series and holdings must come from snapshots. Draw no chart when no history exists; show a dashed empty panel. Missing cost remains unknown even when a price is zero. Do not invent a transaction reference or persisted imported-type/edited flag.

The approved images do not define loading/error/toast or sync-popover pixels for Coin detail. The existing route initialization overlay remains while the page initializes; the Coin cards then show available values or dashes as their independent queries settle. A failed card query now shows a Retry action. The sync popover and mutation error toast retain their existing behaviour. A failed save preserves the entered values; a successful save closes and refreshes through the existing data-change event.

## Remaining differences

- Content-sized wide layouts keep Holdings by source in the right column and Open lots below the chart on the left. If either column is over 1.5 times taller, the shorter column follows scrolling within the grid. Transactions begin after the taller column, so their vertical position differs from the static reference. Sources with no balance occupy one expandable row; more than ten non-zero sources remain nine rows plus Others. Lots initially show eight rows, with an expandable scroll area for the full list. Short chart histories show an inline hint instead of an empty plot. At 1100–1300px, hero values scale down and notes wrap to keep all text visible.
- The header keeps the live total, DatePicker, Refresh, and sync-status popover because they are existing portfolio controls absent from the static design. `Updated 09:41` describes a local refresh; the source's `Synced 09:41` would incorrectly imply S3 synchronization.
- Stored assets have a ticker and type but no reliable full name or company name. The headings therefore use BTC, NVDA, and NOVA; the NVDA subtitle says it is held at its broker without claiming `NVIDIA Corporation`. The stock price feed also lacks NASDAQ and delay metadata, so its price note says `Per NVDA, all sources`.
- Stored transactions have no original imported type, edited flag, linked transfer endpoints, or order reference. The `Edited` pills, BTC `from`/`to` transfer labels, and sell-sheet order number in the source cannot be recovered. The BTC edit dialog shows the effective type and Reset clears pending edits.
- The transaction table includes the requested Note column, although the reference header does not. Stored transactions have no note field, so each cell shows a dash. Phone transaction rows expose the same label to screen readers.
- Actual FIFO rounding yields BTC Unrealized P&L `+$23,317.27` and one lot gain `+$2,821.05`, each one cent below the invented values in the source.
- A real custom asset contributes to the real portfolio total. NOVA therefore shows its share instead of the source's `Not in portfolio total`, and the page omits the source's `Sample data` footer, which would be false for a user's asset.
- The NOVA edit dialog presents labeled, read-only asset type and current price values. They cannot be changed by the transaction update command, and clicking them no longer discards a pending edit. The current price is edited with the separate `Set current price` control after closing the transaction dialog. The read-only type field has no dropdown chevron, unlike the source illustration.
- Outside the fixed fixture, chart ticks follow actual timestamped snapshots, so dates and line positions vary with the user's history.
