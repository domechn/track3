# Refresh source failures

`fetchPortfolios` runs one task per active exchange account, wallet address, and stock broker. ERC20 covers each configured EVM address; BTC, SOL, DOGE, TRC20, TON, and SUI cover each address on their respective chain. Manual `Others` entries form one local source. Addresses on the same chain run one at a time; BTC, DOGE, TON, ERC20, and TRC20 have a one second gap between addresses. Account and SOL tasks have a 120 second deadline to allow for sequential provider calls and rate limit retries. Other tasks have a 30 second deadline. A timed out task is excluded from the snapshot. In-flight provider calls can finish after the deadline; cache generations prevent their late results from repopulating cleared balance caches.

An exception or deadline produces a source status of authentication/invalid key, network/timeout, rate limit, unsupported, or other. Upstream exception text and request URLs are never put in status messages, telemetry, or refresh toasts. Optional exchange products denied by permissions or not opened are treated as empty. Network errors, rate limits, and server errors on optional products still fail the owning source. Unknown or unpriced Solana tokens are skipped without failing the wallet.

**Snapshot policy:** a full refresh with at least one successful source saves successful holdings and carries the last persisted amounts for failed wallet identities, including holdings worth less than $1. Carried amounts use current prices when available and their saved baseline price if a fresh price lookup fails. Stale price lookups finish before the database write queue is acquired. A carried holding is shown as **Stale** in the source status dialog and creates no synthetic sale. When a failed identity has no saved holdings, it contributes no assets; the dialog shows **Failed** and warns that totals may be incomplete. A failed source is never written as a zero balance. If every source fails, no new history point is saved. The status button stays visible after closing the dialog, and its non-secret status metadata is stored locally so the warning remains visible after an app restart.

Manual entries can be attached to an exchange or chain wallet and therefore share its stored identity. If one of those sources fails, the saved row cannot be separated into its earlier contributions. Refresh retains that exact aggregate as stale until retry. This avoids double counting and an unproven sale.

**Single-source retry:** Retry clears fetch cache and loads only the selected account or address. It replaces that source's in-memory result from the completed refresh, combines the other source results, and commits a new history point against the latest persisted snapshot. A failed retry leaves the snapshot unchanged. If configuration or a newer snapshot has changed since the completed refresh, retry asks for a full refresh so older source results cannot overwrite newer holdings. After an app restart, the warning remains visible; a full refresh is needed to restore the in-memory source results used by single-source retry.

Currency rate updates are nonfatal. Price aggregation and database persistence remain shared steps: if either fails, the previous committed snapshot remains in place and refresh shows a generic error.
